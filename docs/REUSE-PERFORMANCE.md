# Isolated responsiveness prototype — phase 1

Base: canonical local `92ea92e208c815fc220bac2eb95f988be10faae9`, exact deployed-tree `2ad102c345e7cb8c1cdef719c77fc1768dad3634`. This branch does not deploy or change the photographic shader, temporal samples, geometry, resolution policy, exposure controller or user controls. The existing dirty rendering, hidden-tab pause, 30FPS animation limit and bounded preview resolution are baseline features, **not** new optimizations.

## Measured candidate, not an accepted speed claim

Static inspection identifies blocking GPU-to-CPU reads for ambient metering, histogram and the detail magnifier. Histogram output was rendered and read on analysed frames even with the histogram hidden. The candidate removes that unused hidden-aid work and uses **Three.js 0.186.1's existing `readRenderTargetPixelsAsync`** for the two display-only aids. The ambient meter deliberately stays synchronous: M/A/S/P and Auto ISO still resolve from the current instantaneous ambient image before drawing the current photograph.

Three issues an immediate pixel-pack-buffer copy, then polls a fence before copying bytes to JavaScript. No custom readback implementation, new dependency or UI panel is added. Each aid permits at most one in-flight read and reuses its byte buffer once that slot frees. Invalidation cancels delivery, not Three's owned GPU operation; changed user controls, selected scene/view, hidden aids and changed photographic hover crops reject delivery. A histogram which changes while pending coalesces to a single newest target snapshot and drains after completion, without redrawing the whole photograph. Detail rendering restores all main render bindings **before** the fence wait. Aid completion only writes its canvas; it never dirties metering or the photograph.

**Motion snapshot policy:** these display-only aids show the latest completed photographic snapshot for the unchanged user/scene/view revision, not an impossible guarantee of the latest animation serial. Motion and AF-C may therefore trail by the one in-flight read (histogram additionally retains only one newest pending target); no queue of old snapshots accumulates. `data-source-frame` and `data-source-time` identify the actual delivered snapshot. A previously completed magnifier image stays visible while its unchanged moving crop waits for a newer sample. Changed user focus/exposure/scene/crop still cancels old delivery; frozen/paused photographs remain exact. Requiring equality with each new animation frame would starve the aids whenever a fence took more than one frame. Delayed-fence tests explicitly require both aids to advance while every read spans at least two newer photograph frames, as well as pointer movements within an identical clamped crop.

No selected-view prewarm has been enabled without evidence: `compileAsync`/`initTexture` remain options only if measurements show first-use compilation/upload is the actionable bottleneck and account for any extra load delay. There is no all-view preload, custom DOF rewrite, lower sample budget or hidden resolution reduction.

## Evidence and limits

`?diagnostics=performance` adds a read-only `window.__cameraDiagnostics.snapshot()` with bounded CPU stage history for whole preview callbacks, meter, photograph and magnifier. Each photograph measurement encloses the full pipeline, not a single draw. API pass counts include nested reflection calls, but do not add `renderer.info` draw totals (nested renders can reset them); the identical external harness counts native WebGL draws accurately. CPU submission/block time is **not GPU completion or device FPS**. Normal operation retains no diagnostic history and has no diagnostic panel.

See [`tools/performance/README.md`](../tools/performance/README.md) for the identical external Playwright instrumentation, full-RAF/timer-query definitions, fixed-quality scenarios and before/after provenance. `EXT_disjoint_timer_query_webgl2` absence remains an explicit missing GPU result; `gl.finish` is not used to pretend GPU completion. CI uses SwiftShader and cannot establish real-device smoothness.

Before acceptance, inspect every alternating comparison round, exact photograph pixel differences, first-load and aid delivery latency as well as CPU/readback cost, then the complete browser regressions. Unit tests cover backpressure, logical cancellation, queued latest-only delivery, no redraw scheduling and immediate main-state restoration; browser tests deliberately delay GPU fences to exercise obsolete focus/scene/position/hide results. Local browser execution is blocked by the environment and is not retried; the read-only isolated-branch CI is the supported browser route. Until its actual results are available, no speed improvement is claimed.

Primary API source: installed `three/src/renderers/WebGLRenderer.js`, `readRenderTargetPixelsAsync` (PBO submission, fence polling, asynchronous buffer copy), and [Three.js WebGLRenderer documentation](https://threejs.org/docs/#api/en/renderers/WebGLRenderer.readRenderTargetPixelsAsync).
