# 四景摄影路径阶段验收（2026-10-18）

结论：四个源场景已进入同一摄影路径，每景七个真实拍摄机位、按需资源、曝光/景深/对焦和独立闪光均可运行。此版本可从干净 Git 检出重建并继续开发。它是用户认可的有界摄影机架方案；连续整屋自由移动仍仅在保留的 `?renderer=gltf` 路径中，不能把摄影图的拖动称为真实平移。

本报告替代较早 QUALITY.md 中的待办状态。全部截图来自 `npm run build` 后的 `npm run preview`，Chrome155 无头浏览器，桌面1440×1000、窄屏390×844；没有使用 Vite dev 作为交付验收。

## 证据纠正

`35b9566` 中最初提交的25/26/27整页PNG只有取景区CSS背景，RGB恒定为(22,23,25)、标准差为0，不能支持当时的三景截图通过结论。本轮已替换这些图片，并逐张实看桌面版与新增加的390px窄屏版。代码修复了截图/隐藏布局期间ResizeObserver把零宽度转成1×1而清空画布的问题；真实尺寸变化会先撤销旧ready标记，再重绘。该缺陷不是源场景素材缺失。

新的整页截图直接从PNG裁出取景区域检查内容，没有把独立Canvas图贴进页面。教室、厨房、公寓桌面标准差分别49.23、47.20、40.58，有效内容像素约94.0%、96.9%、75.9%；[原始数值与尺寸](final-page-pixel-evidence.json)保留了对应状态。四景回归同时检查首次中心及每个后续机位的整页图像方差和有效内容比例，避免CSS背景均值23.3也通过的旧漏洞。隐藏后恢复、390/1440px尺寸切换和展开辅助项另有实际图像回归。

生产重拍命令：设置`PW_BASE_URL=http://127.0.0.1:8002`、`PW_CHANNEL=chrome`后运行`node tools/capture-scene-review.mjs`。每张最终PNG在写入后执行同样的内容检查，断言失败即停止。

闪光失败缓存也已修正：切到正常机位会清除旧错误，返回失败机位或切房间再返回时可重新请求，不再出现滑杆已开启而失败缓存永久阻止闪光的情况。对应回归实际中止网络请求后走完整恢复路径。

短快门闪光现在在第一个HalfFloat缓冲之前统一预曝光，源场景、实时物体、景深和时域积分共用同一尺度，最终显示时恢复曝光单位。真实理发店1/8000s闪光的未缩放峰值约716772，预曝光后最高4452，非有限值0；固定光圈/ISO，与1/125s的能量差约0.000056EV。强HDR夹具、实时风扇脉冲和保留的glTF背景也验证了相同性质，详见[GPU数值证据](final-flash-hdr.md)。该修复保留HalfFloat/MSAA与原有闪光瞬间时序。

## 数值与行为证据

四景基础审计分别得到7张不同的辐射图、7张不同的Z图、单位尺度相机矩阵和正确物理位移。首次位置的图像/Z合计约2.11、2.65、2.52、1.72MiB；冷启动不请求其他房间和GLB。各景其余基础机位合计约14.72、18.66、17.67、12.09MiB；可选高清和闪光不计入首次资源。

28张静态闪光图全部重新生成并通过源SHA、实际相机、near、offset和灯位置校验。曾发现非中心机位的灯未跟随更新；本轮全部纠正，未将错误版本当作最终资产。每层独立HDR范围避免高亮静默截断，clampedChannels均为0。理发店与公寓源相机在切面墙后，闪光发光点分别前移1.5m和4.4m，属于声明的场景内补光位置。

点击球体得到实际距离：教室2.152m、厨房2.118m、公寓7.090m；快门对比保持这些距离。三景AF-C在解除暂停后均继续改变距离，AF-S与风扇底座锁定另有回归。快门积分上限24次，快照1次、慢门24次；30秒操作也已实际执行。

线性HDR过滤 fixture 的1/16相邻亮度在GPU中插值得到约8.5；不再在log编码中取几何平均。GPU景深 fixture 中，焦内前景串色为0/255；离焦近物外延4px处为63/255，f/16时为0。732px预览与2048px导出的模糊外延分别22/62px，归一化误差小于2px。PNG导出2048长边，竖幅、快速切换、失败重试和迟到资源不覆盖当前机位均有生产回归。

曝光M/A/S/P、Auto ISO、正EV补偿与选点测光在生产浏览器中验证；白平衡、光圈、快门、焦距、比例、叠加提示与导出也有回归。测试数量只说明覆盖，不替代上述实际画面。

本轮 `npm test` 12项通过，最终生产浏览器回归30项通过；四景基础资产/机位审计通过，生产构建成功。浏览器测试启动命令已改为生产preview，`pretest:browser`强制先构建，CI也执行四景摄影机位审计。首次`npm ci`为41个安装包、42个审计包、0漏洞，之后依赖锁未改变。构建仍报告约719kB的主JS分块警告，实体低端设备性能仍需后续测量。

以上30项是最终生产构建在本机硬件渲染的结果（1.4分钟）。旧提交`35b9566`的[远端CI](https://github.com/BW1145/CameraSimulator/actions/runs/39118757648)为22项通过、2项失败（900ms内AF-C变化不足，以及保留的glTF跟焦测试在折叠项点击时超时）。[复现和测试时序修正](CI_AF.md)保留原有对焦变化阈值，改为先确认实际目标移动；两个对焦测试在相同SwiftShader条件下通过（1.8分钟）。最终提交还须独立核对自身Actions运行；本机截图与测试不能替代远端CI结果。

随后`44c281f`的[远端CI](https://github.com/BW1145/CameraSimulator/actions/runs/39121484604)为29项通过、1项超时：旧glTF组合用例在点测光及补光断言通过后，最后的慢快门截图耗尽180秒预算。[定向复现与测试拆分](CI_METER.md)保持阈值不变、先暂停再启用运动，以相同800×700真实视口分别验证测光/闪光和快门/轨迹。修正版两项SwiftShader测试27秒通过；测试总数因拆分变为31，产品源码未因此改变，仍须核对新提交自身的完整远端结果。

## 交付边界与下一步

七个离散实际机位之间没有连续合成视差；拖动仅做有界转向/取景，焦距与实际移位分开。单层Z不能恢复遮挡后背景与镜面虚像深度；极端散景、细线和长焦裁切仍有采样边界。源Z编码上限64m，厨房远处地面约5.37%高分辨率Z像素饱和为64m，主体约9–20m不受此上限影响。风扇接触阴影与实时物体光照是局部近似。

所有基础机位、静态闪光和高分辨率影像/Z均为四景各7组。新增厨房与公寓完整高清层分别核对约6221万/7177万辐射像素、1555万/1795万深度像素，像素不匹配及辐射截断均为0，原基础/闪光文件哈希不变。详见[厨房审计](kitchen-detail-pixel-audit.jsonl)、[公寓审计](apartment-detail-pixel-audit.jsonl)、[云端交接](../CLOUD_HANDOFF.md)和[资产流水线](../PHOTOGRAPHIC_ASSET_PIPELINE.md)。低端实体手机、云端WebGL和更广泛主观教学体验尚未验证；不据本机模拟结果宣称已完成这些验收。

最终生产构建已逐一按需加载[全部28组高清与Z](final-detail-loads.json)。公寓七机位从200mm/转向返回53mm后的[边界记录](apartment-detail-boundaries.json)无页面异常；[下降机位](34-apartment-hires-down.png)和[后退机位](35-apartment-hires-back.png)已实看。另对原HDR纯黑区配对EXR检查，左/下机位的相关黑像素均对应约4.00–4.26m有限近几何，不是无几何远背景；没有仅因RGB为零就误报空洞，见[深度区分](apartment-detail-black-depth-audit.jsonl)。
