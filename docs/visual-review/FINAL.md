# 四景摄影路径阶段验收（2026-10-18）

结论：四个源场景已进入同一摄影路径，每景七个真实拍摄机位、按需资源、曝光/景深/对焦和独立闪光均可运行。此版本可从干净 Git 检出重建并继续开发。它是用户认可的有界摄影机架方案；连续整屋自由移动仍仅在保留的 `?renderer=gltf` 路径中，不能把摄影图的拖动称为真实平移。

本报告替代较早 QUALITY.md 中的待办状态。全部截图来自 `npm run build` 后的 `npm run preview`，Chrome155 无头浏览器，桌面1440×1000、窄屏390×844；没有使用 Vite dev 作为交付验收。

## 数值与行为证据

四景基础审计分别得到7张不同的辐射图、7张不同的Z图、单位尺度相机矩阵和正确物理位移。首次位置的图像/Z合计约2.11、2.65、2.52、1.72MiB；冷启动不请求其他房间和GLB。各景其余基础机位合计约14.72、18.66、17.67、12.09MiB；可选高清和闪光不计入首次资源。

28张静态闪光图全部重新生成并通过源SHA、实际相机、near、offset和灯位置校验。曾发现非中心机位的灯未跟随更新；本轮全部纠正，未将错误版本当作最终资产。每层独立HDR范围避免高亮静默截断，clampedChannels均为0。理发店与公寓源相机在切面墙后，闪光发光点分别前移1.5m和4.4m，属于声明的场景内补光位置。

点击球体得到实际距离：教室2.152m、厨房2.118m、公寓7.090m；快门对比保持这些距离。三景AF-C在解除暂停后均继续改变距离，AF-S与风扇底座锁定另有回归。快门积分上限24次，快照1次、慢门24次；30秒操作也已实际执行。

线性HDR过滤 fixture 的1/16相邻亮度在GPU中插值得到约8.5；不再在log编码中取几何平均。GPU景深 fixture 中，焦内前景串色为0/255；离焦近物外延4px处为63/255，f/16时为0。732px预览与2048px导出的模糊外延分别22/62px，归一化误差小于2px。PNG导出2048长边，竖幅、快速切换、失败重试和迟到资源不覆盖当前机位均有生产回归。

曝光M/A/S/P、Auto ISO、正EV补偿与选点测光在生产浏览器中验证；白平衡、光圈、快门、焦距、比例、叠加提示与导出也有回归。测试数量只说明覆盖，不替代上述实际画面。

本轮 `npm test` 12项通过，最终生产浏览器回归24项通过；四景基础资产/机位审计通过，生产构建成功。浏览器测试启动命令已改为生产preview，`pretest:browser`强制先构建，CI也执行四景摄影机位审计。首次`npm ci`为41个安装包、42个审计包、0漏洞，之后依赖锁未改变。构建仍报告约718kB的主JS分块警告，实体低端设备性能仍需后续测量。

## 交付边界与下一步

七个离散实际机位之间没有连续合成视差；拖动仅做有界转向/取景，焦距与实际移位分开。单层Z不能恢复遮挡后背景与镜面虚像深度；极端散景、细线和长焦裁切仍有采样边界。源Z编码上限64m，厨房远处地面约5.37%高分辨率Z像素饱和为64m，主体约9–20m不受此上限影响。风扇接触阴影与实时物体光照是局部近似。

所有基础机位与静态闪光完整。高分辨率层的逐景状态及继续生成命令见 [云端交接](../CLOUD_HANDOFF.md) 和 [资产流水线](../PHOTOGRAPHIC_ASSET_PIPELINE.md)。低端实体手机、云端WebGL和更广泛主观教学体验尚未验证；不据本机模拟结果宣称已完成这些验收。
